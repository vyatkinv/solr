# Proposal: add-write-load-balancing

## Why

В проде кластер принимает записи через ротацию головных коллекций: каждый логический индекс пишет в голову, раскрытую через алиас с суффиксом `_WRITE`; при превышении порога создаётся новая пустая коллекция и алиас мгновенно переключается на неё. Коллекции создаются часто и мелкие (1–2 шарда).

Существующие weight-based плагины размещают новые реплики на «самых лёгких» нодах. Свежедобавленная пустая нода строго выигрывает каждое сравнение, поэтому она получает ~100% новых write-потоков, пока не догонит кластер по cores — это в 3–5 раза больше записи на ноду, чем у старых нод, и приводит к CPU saturation. Введённый ранее пер-коллекционный лимит `placement.maxReplicasPerNode` не помогает: он ограничивает реплики одной коллекции на ноде, а write-нагрузка накапливается across-коллекциями — по одной микроколлекции на ноду размещать не запрещено.

Свободное место и cores в момент размещения — плохой прокси для write-нагрузки: новая write-голова создаётся пустой. Нужен отдельный критерий баланса — счётчик write-реплик на ноде.

## What Changes

- **Расширение placement API**: интерфейс `Cluster` получает метод `getCollectionAliases()` (карта алиас → коллекции), имплементация читает алиасы из ZK-backed провайдера на Overseer-пути. Алиасы — единственный источник истины о write-головах.
- **Write-учёт в базовом плагине**: `OrderedNodePlacementPlugin.WeightedNode` аккумулирует per-node счётчик write-реплик в существующем цикле `initReplica` (без обращений к `AttributeFetcher`).
- **Правило write-ности**: коллекция write ⇔ она отсутствует в cluster state (CREATE/SPLIT — новая коллекция всегда write) ИЛИ состоит в алиасе с суффиксом `_WRITE`. После ротации голова выпадает из `_WRITE`-алиаса и её реплики перестают считаться.
- **Новый доминантный член веса в Simple**: `10 000 × writeReplicasOnNode`; проекция write-реплики добавляет тот же член. Read-only размещения тоже видят этот член в весе ноды (единая «эффективная загрузка»), но не увеличивают его.
- **Жёсткая анти-аффинити в Simple**: `canAddReplica` вызывает `super` — две реплики одного шарда на ноде запрещены (раньше — штраф). Иначе write-доминанта заставила бы стекать обе реплики RF=2 на пустую ноду во время ramp.
- **Попутный фикс апстрим-бага**: в `SimplePlacementFactory.addedWeightOfAdditionalReplica` инкрементальный штраф за реплику того же шарда вычислялся от счётчика коллекции (`colReplicaCountWithout` вместо `shardReplicaCountWithout`).
- Гарантированное свойство: bounded ramp — `write(нода) ≤ write(любая нода) + O(1)`; баланс самоподдерживается после ротаций без BALANCE_REPLICAS.
- Нулевое изменение поведения для кластеров без `_WRITE`-алиасов (write-член = 0, формула вырождается в сегодняшнюю).

## Capabilities

### New Capabilities
- `write-load-balancing`: размещение реплик с балансировкой write-нагрузки — правила определения write-коллекций, весовая модель, инварианты и влияние на операции (CREATE, ADDREPLICA, SPLITSHARD, repair, балансировка).

### Modified Capabilities

(нет — спецификаций в репозитории ранее не существовало)

## Impact

- **Код**:
  - `solr/core/src/java/org/apache/solr/cluster/Cluster.java` — новый метод API
  - `solr/core/src/java/org/apache/solr/cluster/placement/impl/SimpleClusterAbstractionsImpl.java` — имплементация алиасов
  - `solr/core/src/java/org/apache/solr/cluster/placement/plugins/OrderedNodePlacementPlugin.java` — write-счётчик в `WeightedNode`
  - `solr/core/src/java/org/apache/solr/cluster/placement/plugins/SimplePlacementFactory.java` — формула веса, `canAddReplica`, фикс бага
  - тестовая инфраструктура `Builders` — поддержка алиасов
- **Прод**: плагин не меняется (Simple — дефолт), включение автоматическое при наличии `_WRITE`-алиасов; ротационный сервис не требует изменений.
- **Совместимость**: без `_WRITE`-алиасов поведение побайтово сегодняшнее; существующие тесты плагинов не затронуты.
- **Upstream-потенциал**: расширение API алиасами и write-балансировка оформляемы как improvement в Apache Solr (по образцу наброска для `maxReplicasPerNode` в `PLACEMENT-PLUGINS.MD`).
